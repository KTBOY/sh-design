# 奶油白 3D 产品街区

## 角色与目标

作为兼顾产品信息架构、三维构图和前端工程的实现者工作。

把城市变成产品目录：**背景楼群负责氛围，前景地标代表产品，选择建筑就是选择产品。**

验收底线：关掉动画仍能快速找到产品；打开动画能更直观地理解产品能力。

用户要求优先于本 Skill 的视觉默认值。先遵守目标仓库的规范，不把本仓库的文件名、Vue 实现或产品数量强加给其他项目。

## 何时使用

- 为首页、作品集或工具聚合区创建具有业务交互的 Three.js 城市场景。
- 将“纯背景城市 + 无关卡片墙”改成建筑与产品信息联动。
- 为已有产品街区增加地标、调整主题、改善移动端或完善降级。

不是给所有网站加 3D 的理由。不适用于真实地理信息、实时监控、第一人称游戏，也不默认加载完整产品应用。

## 快速使用示例

- “使用 threejs-product-district，为当前首页的产品做奶油白街区，其余按默认，直接实现。”
- “使用 threejs-product-district，读取指定产品组件，先给桌面和移动端设计，不修改代码。”
- “沿用这个 Skill 的交互，把七个产品换成我的五个项目，品牌色改成绿色，保留列表入口。”
- “给现有街区增加一个图表产品，检查产品排序变化后建筑是否仍正确对应。”

## 1. 先确认边界

从用户输入和仓库读取事实，能合理推断的内容不要反复询问：

| 要确认的事实   | 验证动作                                                 |
| -------------- | -------------------------------------------------------- |
| 改哪个区域     | 找到实际挂载入口，区分首页、旧组件和独立聚合页           |
| 产品从哪里来   | 读取数据源、稳定标识、名称、说明、标签和链接规则         |
| 当前设计语言   | 读取背景、品牌色、字号、圆角、边框、内容宽度与主题策略   |
| 技术约束       | 检查框架、SSR/SSG、Three.js 依赖、构建与测试脚本         |
| 要设计还是实现 | 只要想法时不给仓库写实现；明确授权实现后按已定方案推进   |
| 尚缺什么       | 列出真正影响范围的决策和验证动作，不虚构接口或已执行结果 |

默认边界：只替换产品区域，保留全站导航、其他页面和原产品链接；不新增登录、后端、权限系统或分析埋点。变更依赖、全站主题或其他区域前说明必要性，不顺手扩张范围。

若需要确认设计，用三个明确默认值：

- **D1 范围**：只改产品区。
- **D2 交互**：固定斜俯视沙盘，不做自由漫游、不劫持滚动。
- **D3 入口**：城市为默认主视图，原卡片作为可切换列表，聚合页仍可访问。

这些默认值已经被用户批准时，不再重复请求批准。

## 2. 先做产品与建筑的语义映射

先列“稳定 ID → 产品能力 → 建筑形态 → 一次短动画”，再建模。建筑不能只是七个相同盒子贴七张名称。

| 产品能力             | 建筑隐喻             | 选中反馈                   |
| -------------------- | -------------------- | -------------------------- |
| 组件与模块组合       | 阶梯式组件中心       | 模块轻微分离、组合后归位   |
| 图表与数据表达       | 高低错落的图表塔     | 柱体短暂变化高度           |
| 星空、壁纸、图像内容 | 圆顶观测馆           | 天文圆环转动、少量星点亮起 |
| 跨端组件             | 双楼连桥实验室       | 两侧界面窗口同步亮起       |
| 复古游戏工具         | 低矮街机馆           | 像素门头短暂亮起           |
| 写作与知识图谱       | 中央书塔及环绕阅览馆 | 少量节点与连线展开         |
| HUD 与交互设计       | 白色展馆、深色内厅   | 局部金色 HUD 线框展开      |

这张表是创作参考，不是强制产品清单。其他产品应重新提炼能力，不套用不相关的建筑。

- 主要地标位于中央和前景；普通楼群退到外围，降低高度和对比度。
- 用建筑轮廓区分产品，用小面积强调色表达选择，不把整栋楼染成品牌色。
- 道路只组织空间，不伪造产品依赖关系、实时流量或业务数据。
- 动画是能力隐喻：不为了展示 Flash 加载模拟器，不为了小说产品启动完整编辑器。
- 产品数量增加时重新验证构图与标签密度，不能简单把新地标塞进旧坐标。

## 3. 默认视觉配方

采用建筑工作室实体沙盘的质感，而非霓虹科技大屏。

| 项目        | 起始值                                                   |
| ----------- | -------------------------------------------------------- |
| 场景背景    | 暖白 `#f3f0e7`，轻微柔和明暗层次                         |
| 墙体 / 石材 | `#f5f1e7` / `#e5dfd2`                                    |
| 地面 / 道路 | `#eeeae1` / `#d1cec5`                                    |
| 屋顶 / 玻璃 | 香槟 `#d3c6ac` / 灰绿 `#b4c0bc`                          |
| 交互强调    | 优先现有品牌色；本例为 `#2563eb`                         |
| 信息区      | 白底、细边框、16px 圆角；墨色标题、灰色正文              |
| 信息层级    | 等宽编号、产品名、说明、胶囊标签、明确链接按钮           |
| 环境层次    | 弧线河道、浅拱桥、滨水步道、远岸低丘和口袋公园，只做背景 |
| 桌面起点    | 外层最大宽 1152px；城市约 500px 高；右侧说明约 310px 宽  |
| 移动起点    | 上方约 350px 高城市，下方详情及完整作品索引              |

以上是构图起点，不是跨项目固定规范。优先使用目标站点已有的设计令牌、字体和宽度。

- 固定斜俯视正交相机，清楚展示屋顶、正面与道路，不用持续旋转制造动感。
- 柔和日光、接触阴影、低分段圆角几何；先把体块和阴影做好，再补门窗、台阶、树木和路灯。
- 不默认引入 Bloom、景深、SSAO、车辆系统或大型外部模型。
- 河岸、山丘、公园只接收光照和阴影，不进入拾取集合；可点击对象始终只有产品地标。
- 水面流动要同时提亮和压暗（明暗双向带 + 少量高光），只提亮的微弱高光肉眼看不出动；不默认启用实时反射或大面积水波着色器。
- 远丘用连续缓丘网格，横截面的落回指数取 > 1（如山脚切线落地），否则山脚会留一条硬折痕；顶点色两端提亮、中段加深，再配树线打散轮廓，避免重复等比椭圆。
- 自定义河道等几何参与静态合批时，对齐已有 position / normal / uv 属性；合批失败会中断整个场景创建。
- 深色页面仍应保证信息面板对比度；不为这个局部组件改变全站主题开关。
- 输出或查看桌面、窄屏构图；发现地标遮挡、标签碰撞或标题不清楚时先改构图，不继续堆装饰。

## 4. 信息与交互契约

保留一份权威产品数据，建筑配置只补充形态、位置和铭牌短名，不复制产品介绍和网址。

推荐职责拆分，而不是要求目标项目已经有这些接口：

1. **产品资料**：稳定 `id`、名称、说明、标签、链接及站内外语义。
2. **建筑配置**：`id → 地标类型、位置、短名、动画`。
3. **Three.js 场景**：模型、拾取、选择反馈、镜头、投影坐标和资源释放。
4. **框架界面**：城市/列表切换、详情面板、DOM 铭牌、作品索引和可访问状态。

至少分清 `selectedId`、`hoveredId`、当前视图、加载/失败、减少动态偏好。不要把悬停当选择，也不要通过 DOM 闪烁类名承担权威状态。

### 必须实现的操作

- 初始默认选中主产品或第一个有效产品；无需探索城市才能找到入口。
- 悬停建筑：只强调入口与铭牌，不改变详情，不触发跳转。
- 点击建筑或铭牌：选中产品，更新同一张详情面板，播放一次短动画。
- 点击作品索引：反向选中对应建筑，所有产品始终可达。
- 只有点击详情中的真实链接才导航，保持原有站内 `base`、站外标签页和安全属性。
- 提供全景复位和城市/列表切换；切回城市保留所选产品。
- 列表沿用原卡片；不在城市下方默认重复展开整套卡片墙。
- 新产品缺少模型配置时，仍通过索引、详情或列表可达；不能悄悄丢掉产品。

### 输入与无障碍

- 铭牌和产品索引用真正的 DOM 按钮，提供可见焦点、完整可访问名称及选择状态。
- 产品文本和链接保持 DOM 排版，不把必须阅读的内容画进 WebGL 纹理或倾斜 CSS3D 卡片。
- 触屏不依赖 hover；按下与抬起在同一地标、且移动距离不超过阈值才视为点击，避免滚动误触。
- 移动端可将场景铭牌缩为编号，但必须保留完整名称的作品索引和可访问标签。
- 不拦截页面上下滚动，保留触屏缩放；不隐藏部分产品冒充移动端适配。
- DOM 铭牌悬停或键盘聚焦时，清空待处理的 canvas 指针事件，防止上一帧拾取结果覆盖高亮。
- 场景失败并卸载时，若焦点在场景内部，将焦点恢复到列表切换等可用入口。

## 5. Three.js 实现纪律

- 复用已有依赖；保持 Three.js 在场景异步入口之后，不进入普通产品列表的必要加载链。
- WebGL、观察器及浏览器事件只在客户端挂载后创建，保证 SSR/SSG 不读取 `window` 或 `document`。
- 产品 ID 与地块绑定，不按数组索引绑定；编号可以随展示排序变化，建筑归属不变。
- 地标网格或祖先保存产品 ID；Raycaster 只检查可交互地标，背景楼群不可误选。
- 地标屋顶使用世界坐标锚点投影到 DOM，窗口变化时重算；同时检查遮挡、边缘裁切和铭牌碰撞。
- 共享几何和材质；合并同材质静态装饰，但保留动态部件、地标祖先、可见性及阴影语义。
- 动画由一个场景调度器驱动，不给每栋建筑创建独立 RAF 或定时器。
- 短动画默认约 1100ms，两端显式归位；快速切换产品必须复位上一个动画，不能依赖 `sin(π)` 恰好为零。
- 减少动态时立即呈现最终静止状态，保留选择、信息和导航，不默认关闭所有功能。
- 可按需渲染；持续性环境动画（如水面细纹）单独开环：只在舞台可见、页面前台且未开启减少动态时以约 20–25 fps 驱动，离屏、切后台和减少动态时必须停止循环。
- 开启水面循环后关闭静态街区的阴影自动更新，只在镜头/地标动画和尺寸变化时重算阴影。
- 起始 DPR 上限可取桌面 2、小屏 1.5；单个方向光阴影贴图先用 1024，再根据目标设备测量调整。
- 相机按地面和建筑包围范围与容器宽高比拟合，不能只针对一个桌面尺寸硬编码视野。

### 加载、失败和清理

- 进入产品区附近再动态加载，例如 `IntersectionObserver` 的预加载边距约 250px。
- 加载期间仍可阅读产品面板、使用索引和切换列表；首次成功绘制后才宣布场景就绪。
- 异步导入失败、WebGL 初始化失败、渲染异常或 context lost 时回到完整列表，给出可理解的提示与重试入口。
- 未挂载完成就离开页面时，异步结果不得重新挂载组件；使用卸载标记防护。
- 卸载成对清理 RAF、事件、观察器、几何体、材质、纹理、阴影贴图及 renderer。
- 共享资源去重释放，dispose 幂等；部分初始化失败也要清理已经创建的资源。
- 不触碰当前组件之外的 canvas、浏览器实例或全局事件所有权。

## 6. 按小步实施并验证

1. **定构图**：明确目标、非目标、约束、产品映射及桌面/移动布局。
2. **单地标闭环**：先验证“选择建筑 → 产品详情 → 正确链接”，同时保留列表。
3. **扩展所有地标**：补齐轮廓、短动画和双向选择，检查重排与新增产品。
4. **完善生命周期**：加载/失败、减少动态、输入边界、离屏与资源释放。
5. **局部检查与视觉回归**：通过后报告结果，不把完成代码等同于通过实机验收。

### 自动化与静态检查

- 产品 ID 唯一；每个已有地标对应有效产品及链接。
- 产品重排不改变地标归属和坐标；未知或缺省映射有明确行为。
- 地标可拾取；动画结束和快速切换后归位；资源仅释放一次。
- 检查相关文件的类型、lint、格式以及生产构建/SSR。
- 先确认命令真正覆盖修改区域；组件库的类型检查不一定覆盖文档站。
- 不运行全仓格式化来处理局部功能，不顺手修复无关基线问题。

### 浏览器验收

- 至少覆盖桌面与窄屏，例如 1440px、390px；再根据目标增加断点。
- 建筑、铭牌、作品索引、键盘选择和详情保持一致；标签可读、不碰撞，不横向溢出。
- 多次城市/列表切换只保留一个有效 renderer，并保留选择状态。
- 减少动态下功能完整、水面静止，且没有城市持续绘制；正常模式可见时允许低频水面动画。
- 用固定视口的两次截图或绘制计数证明水面正常动画，并验证离屏、后台和减少动态时绘制停止。
- 模拟 WebGL 不可用及上下文丢失，确认完整列表、焦点恢复和重试。
- 核对站内链接、站外链接和真实跳转；预览截图不等于验证跳转。
- 记录异步包原始及 gzip 字节、模型复杂度、实际设备结果；同口径比较，不编造帧率或体积收益。
- 不提高 chunk 告警阈值掩盖包体积问题，也不把体积告警说成构建失败。

视觉改动优先查看真实截图。隐藏浏览器的 `0×0` 视口不代表页面故障；截图不可用时明确记录未验证项，不冒充视觉验收。

Windows 无头 Edge 的启动进程可能先以 0 退出，但独立 profile 内实际浏览器仍运行。可核对该 profile 的 `DevToolsActivePort` 再连接 CDP；仅管理本次创建的实例，不结束用户其他浏览器进程。截图与临时探针放仓库外；清理 profile 前确认实例已退出。
