## 1. 设计判断

我把它读成：面向城市网约车司机的工具型小程序，使用场景在车内、单手、强光、时间敏感，视觉倾向 Uber 式黑白高对比与单一胶囊形状。

### 三档旋钮

| 旋钮             | 取值 | 理由                                                                   |
| ---------------- | ---- | ---------------------------------------------------------------------- |
| DESIGN_VARIANCE  | 4    | 司机在 3 秒内要读完订单，结构必须可预测，不能靠不对称版式制造惊喜      |
| MOTION_INTENSITY | 3    | 只保留接单成功、状态切换、按钮按压三类反馈，行驶中不做装饰动效         |
| VISUAL_DENSITY   | 5    | 高于营销站，低于驾驶舱。单卡承载价格、距离、时长、起终点，但不堆统计图 |

## 2. 风格选择：Uber

### 2.1 选择理由

- 司机端是工具，不是营销页。Uber 的黑白双色系统天然抗眩光，白天车内也能一眼分清主次。
- 胶囊按钮的触控面积大，适合单手拇指操作。
- 不用 TDesign 默认蓝色。蓝色是网约车平台的通用色，无法建立识别度，也会让状态色和品牌色混在一起。
- Uber 的版式克制，和 TDesign 的组件结构兼容，改造成本低。

### 2.2 落地改造

| Uber 原始 token       | 本项目取值   | 原因                                           |
| --------------------- | ------------ | ---------------------------------------------- |
| ink `#000000`         | `#111111`    | 避免纯黑，保留同等对比度                       |
| canvas `#FFFFFF`      | `#F6F6F4`    | 页面用暖白，卡片仍为白色，拉开表面层级         |
| canvas-soft `#EFEFEF` | `#EDEDEA`    | 与暖白底同色相，避免发灰                       |
| body `#5E5E5E`        | `#5E5E5E`    | 直接沿用，白底对比度 6.48:1                    |
| pill 999px            | 999rpx       | 主按钮、筛选 chip、标签全部胶囊                |
| card 16px             | 32rpx        | 订单卡、资料卡、底部面板统一 16px              |
| display 52px          | 28px 至 32px | 手机首屏标题不需要 52px，避免挤压订单列表      |
| 编辑插画              | 不启用       | 司机端使用真实地图与真实数据，不用插画伪装内容 |

形状规则只留两种：交互元素用胶囊，容器用 16px 圆角。输入框是唯一例外，使用 12px 圆角，避免和按钮混淆。

## 3. 产品分析

### 3.1 用户与场景

- 用户：25 至 50 岁的网约车司机，熟悉手机但不会研究界面。
- 环境：车内支架、强光、单手、频繁切换应用。
- 心理：怕漏单、怕看错起点、怕接单后联系不上乘客。
- 关键约束：任何主操作都必须在下半屏单手可达；任何订单信息都必须在 3 秒内可判断。

### 3.2 核心任务

1. 看单：当前位置附近有哪些未接订单，价格和距离是否值得接。
2. 判断：起终点、接驾距离、全程距离、预计时长、是否预约。
3. 接单：一次确认，成功后立即进入导航。
4. 履约：联系乘客、查看路线、结束行程。
5. 管理：登录、查看和修改司机资料、查看进行中与已完成订单。

### 3.3 反目标

- 不做收入排行榜、成长体系、活动弹窗。
- 不在接单大厅放长文公告。
- 不用红点堆消息，只有真实待处理状态才出现标记。

## 4. 信息架构与流程

### 4.1 信息架构

```
TabBar
├─ 接单大厅
│  ├─ 订单列表
│  └─ 订单详情与路线
└─ 我的
   ├─ 微信登录
   ├─ 司机资料
   ├─ 编辑资料
   └─ 接单记录
      ├─ 进行中
      └─ 已完成
```

### 4.2 登录策略

- 接单大厅允许未登录浏览订单，降低首次进入门槛。
- 点击「接单」时触发登录拦截，登录成功后继续原订单，不要求用户重新找单。
- 「我的」未登录时直接展示登录页，登录后回到个人中心。

### 4.3 订单状态

```
待接单 -> 已接单（前往接驾） -> 服务中 -> 已完成
             └─ 乘客取消 / 司机取消 -> 已取消
```

| 状态   | 列表标签    | 主操作         |
| ------ | ----------- | -------------- |
| 待接单 | 实时 / 预约 | 接单           |
| 已接单 | 前往接驾    | 导航、联系乘客 |
| 服务中 | 服务中      | 导航、结束行程 |
| 已完成 | 已完成      | 查看详情       |
| 已取消 | 已取消      | 无             |

## 5. 设计原则

1. 先给结论。价格、接驾距离、预计时长放在卡片第一屏，起终点放在第二层。
2. 一屏一个主操作。列表主操作是「接单」，详情主操作是「立即接单」，记录页主操作是「导航」。
3. 黑色只给主操作。次要操作使用白底描边胶囊，危险操作使用红色文字，不用红色大按钮。
4. 状态靠文案和形状表达。颜色只做辅助，不做唯一信号。
5. 触控最小 44 x 44，主按钮高度 48，列表内按钮高度 36 但热区扩展到 44。

## 6. Design Tokens

### 6.1 颜色

| Token           | 值        | 用途                          | 对比度               |
| --------------- | --------- | ----------------------------- | -------------------- |
| ink             | `#111111` | 标题、正文、主按钮底          | 白底 18.88:1         |
| ink-secondary   | `#5E5E5E` | 次级信息、起终点辅助行        | 白底 6.48:1          |
| ink-tertiary    | `#6F6F6A` | 占位符、辅助说明              | 白底 5.05:1          |
| ink-disabled    | `#AFAFAF` | 禁用文字，仅非关键信息        | 白底 2.19:1          |
| canvas          | `#F6F6F4` | 页面底色                      | 与 ink 17.45:1       |
| surface         | `#FFFFFF` | 卡片、底部面板、输入框        | 与 canvas 明度差可辨 |
| surface-soft    | `#EDEDEA` | chip 底、输入框底、分段控件底 | 低对比填充           |
| surface-pressed | `#E2E2DE` | 按压态                        | 仅瞬时状态           |
| hairline        | `#E4E4E0` | 卡片描边、分割线              | 装饰线               |
| on-ink          | `#FFFFFF` | 黑底文字                      | 18.88:1              |
| signal-online   | `#0E7A3D` | 听单中状态点，唯一语义绿      | 白底 5.43:1          |
| danger          | `#C62828` | 取消订单、退出登录确认        | 白底 5.62:1          |
| warning         | `#A15C00` | 预约即将开始                  | 白底 5.19:1          |

颜色规则：

- 全项目只有一个强调色 `ink`。`signal-online` 和 `danger` 只在真实状态出现，不作为装饰。
- 不使用渐变、霓虹、彩色阴影、玻璃拟态。
- 页面底色永远为 `canvas`，卡片永远为 `surface`，两者不同时使用纯白。

实现字体：`-apple-system, "PingFang SC", "Noto Sans SC", "Helvetica Neue", sans-serif`。
数字与大写英文使用 `Geist`，中文使用 `Noto Sans SC`。设计稿同此组合。

| body-sm    | 12 / 18     | 400  | Noto Sans SC | 辅助说明           |

排版规则：

- 标题一律句首大写，不写全大写中文。
- 中文标题不加字距。英文标签只用 0.5px 字距，且仅限 TabBar 标签。

- 正文最大宽度按容器自适应，卡片内文字单行截断，禁止挤压按钮。

| 层级    | 值                               | 用途                   |
| ------- | -------------------------------- | ---------------------- |
| level-0 | 无阴影 + 1px `hairline` 描边     | 普通卡片               |

### 6.6 图标

- 来源：TDesign Icons，线宽 2px，尺寸 20 或 24。
- 图标按钮容器 40 或 44，图标居中。
- 状态点直径 8，仅听单状态使用一次。
- 不使用 emoji、不手绘 path、不用第三方图标混搭。

`segmented-control`

- 尺寸：343 x 40，`surface-soft` 底，36px 圆角，内部两段等高。
- 选中段：白色底、黑色文字、level-1 阴影。未选段：透明底、次级文字。

## 8. 页面规格

所有页面使用 375 x 812 画板。状态栏 62px。除登录页与详情页外，底部使用胶囊 TabBar：容器高 95（12 上内边距 + 62 胶囊 + 21 安全区），胶囊圆角 36，内部 item 圆角 26。

### 8.1 接单大厅

- 入口：启动默认页，TabBar 第一项。
- 目标：让司机在 3 秒内判断一单是否值得接。

**Screen Blueprint**

- Status Bar：标准 62，深色图标，底色 `canvas`。
- App Content：
  - Header：左侧「接单大厅」28/36 粗体，下方「深圳 · 南山区」12/18 次级；右侧听单开关 96 x 36，胶囊，开启为黑底白字加 8px 绿点，关闭为白底描边。
  - Primary：订单卡列表，单卡 343 x 168，间距 12。首屏可见 3 张。
  - Secondary：标题下「今日 8 单 · 流水 ¥326.50」12/18；筛选行 3 个 chip：全部、实时、预约，右侧「距离优先」排序文字。
  - Primary action：每张卡右下「接单」72 x 36 黑色胶囊；点击后弹确认框，确认成功 toast「接单成功，正在为你导航」并跳转详情。
  - Scroll：订单列表纵向滚动，筛选行吸顶在状态栏下 8px。下拉刷新。
- Bottom Bar：胶囊 TabBar，2 项：接单、我的。内容底部预留 95。

**订单卡内容**

| 区域   | 内容                                    | 样式                         |
| ------ | --------------------------------------- | ---------------------------- |
| 标签行 | 实时 / 预约 18:30                       | 胶囊标签，浅灰底，12/16 中黑 |
| 价格   | ¥56.80                                  | 28/32 Geist Bold，右对齐     |
| 起点   | 科技园 · 腾讯大厦                       | 16/24 中黑，单行截断         |
| 终点   | 深圳北站                                | 14/22 次级，单行截断         |
| 距离   | 距您 1.2 km · 全程 18.6 km · 约 32 分钟 | 12/18 三级                   |
| 操作   | 接单                                    | 72 x 36 黑胶囊               |

**卡片样例**

1. 实时：腾讯大厦到深圳北站，1.2 km，18.6 km，32 分钟，¥56.80。
2. 预约 18:30：海岸城到宝安机场 T3，2.8 km，26.4 km，41 分钟，¥82.50。
3. 实时：深圳湾公园日出剧场到平安金融中心，0.8 km，12.1 km，24 分钟，¥38.20。

**状态**

- 加载：3 张骨架卡，保持 168 高度，避免跳动。
- 空：`t-empty` 插图位换成 TDesign 空状态图标，文案「附近暂时没有订单」，按钮「扩大听单范围」。
- 错误：卡片内联错误条「网络不稳定，点击重试」，保留已有列表。
- 收车：列表上方出现浅灰提示条「已收车，开启听单后才会收到新订单」，主按钮变为「开启听单」。
- 未登录：可浏览，点击接单弹出登录页，登录成功后回到原卡片并自动弹出确认框。

## 9. 状态设计

### 9.1 通用状态

| 状态     | 表现                                     | 组件           |
| -------- | ---------------------------------------- | -------------- |
| 加载     | 骨架屏保持原布局高度                     | `t-skeleton`   |
| 空       | 图标 + 一句说明 + 一个动作               | `t-empty`      |
| 错误     | 内联错误条 + 重试，不清空已有内容        | `t-notice-bar` |
| 成功     | 轻提示，1.5 秒自动消失                   | `t-toast`      |
| 离线     | 顶部常驻条「网络已断开，恢复后自动刷新」 | `t-notice-bar` |
| 定位关闭 | 弹窗说明用途，按钮「去开启」             | `t-dialog`     |

### 9.2 接单防错

- 点击接单后按钮立即 loading，禁止重复点击。
- 请求超过 3 秒显示「正在确认订单」，超过 8 秒提示「网络较慢，请稍后重试」。
- 接单成功但页面跳转失败时，toast 提示并提供「查看订单」按钮。
- 订单已被其他司机接走时，弹窗「手慢了，这单已被接走」，自动刷新列表。

### 9.3 表单状态

- 默认、聚焦（1px 黑描边）、错误（1px 红描边 + 12px 红字）、禁用（`surface-soft` 底 + 40% 透明文字）。
- 聚焦态不使用蓝色光晕。

## 10. 动效

| 场景     | 动效                         | 时长  | 缓动                           |
| -------- | ---------------------------- | ----- | ------------------------------ |
| 页面进入 | 内容整体上移 8px + 淡入      | 180ms | ease-out                       |
| 卡片按压 | scale 0.99                   | 120ms | ease-out                       |
| 接单成功 | 按钮收起为成功态，toast 滑入 | 200ms | ease-out                       |
| 分段切换 | 白色滑块位移                 | 160ms | ease-out                       |
| 底部面板 | 从底部滑入                   | 220ms | cubic-bezier(0.2, 0.8, 0.2, 1) |
| 订单刷新 | 列表淡出再淡入               | 160ms | ease-out                       |

规则：

- 只动 transform 和 opacity。
- 不做无限循环动画，骨架屏脉冲除外。
- 尊重系统减少动态效果设置，关闭位移，仅保留淡入淡出。
- 每个动效都能用一句话说明意图，说不清就删除。

## 12. 无障碍与性能

- 正文对比度不低于 4.5:1，主按钮白字黑底 18.88:1。
- 主按钮高度 48，列表按钮热区不小于 44 x 44。
- 所有图标按钮带 `aria-label` 或可见文字，不只靠图形传达。
- 金额、距离、时间同时提供文字标签，不只靠颜色或位置。
- 首屏图片只有地图，采用 2x 静态图，列表不使用大图。
- 骨架屏与真实卡片同高，避免布局跳动。
- 小程序开启 `lazyCodeLoading: requiredComponents`，地图与记录页按需加载。
